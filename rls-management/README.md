# Demo 行级权限管理

入口：http://pbirs.example.internal:8765/ ，使用 Demo 管理员登录，打开“行级权限”。

选择一个普通用户后，汇总读取 PBIRS 中全部 Power BI 报表的已有模型角色与此用户的实际绑定，不必选择报表。同名角色按所属报表区分。当前环境实测 9 张报表、4 个角色，7 张报表无模型角色；读取失败与无角色分别显示。

直接在全部角色列表中勾选，点击“保存全部修改”，跨报表一次提交。已有绑定自动勾选，仅写入有修改的报表。也可从用户管理进入。成员实时读取，保存后再次核对，不另存一套角色或绑定。过滤规则仍在报表模型中定义，Demo 不创建规则。资源查看授权独立管理，模型角色不会自动授予报表查看权限。

后端使用 PBIRS REST DataModelRoles / DataModelRoleAssignments。仅更改目标普通用户，保留其他用户与管理身份。禁止编辑管理员、禁用用户、未知角色及跨报表角色；接口仅允许 Demo 管理员调用。客户端 revision 与保存前重读用于检测过期编辑，Demo 写操作串行化。PBIRS 成员接口为全量替换，没有条件写入，因此无法完全消除原生门户或外部程序在最后一次读取与写入间并发修改的竞态；管理时避免多入口同时编辑。

验证：10 个单元测试通过；共享服务器端到端验证了匿名/普通用户访问隔离、全局角色读取、demo1 从 A 区600切换为 B区1500、其他成员保留、过期与非法写入拒绝、移除角色后无法查询数据。测试已恢复原始 A 区绑定，完整成员分配与测试前一致。见 verification.json、verify.py。

批量接口 /api/admin/rls/user 与 /api/admin/rls/batch：先检查全批次合法性与版本，再逐报表写入，返回每项结果。PBIRS 不支持跨报表事务，部分写入失败会逐项显示，未确认的勾选保留。版本冲突应重新读取核对。

浏览器验收：选 demo1，在两张报表中分别新增一个角色，一次提交，两张均写回核对成功；随后一次提交恢复两张报表原始绑定。截图 batch-roles.png。verify_batch.py 验证跨报表提交、过期批次拒绝、其他成员保留、匿名/普通用户禁止管理以及原始分配恢复。
